## Задача

До этой реализации предварительное сообщение `Where is money` могло показать высокий балл,
но не объяснить, какой источник или маршрут его создал. Общая фраза
`Where Is Money завершил предварительную проверку происхождения средств` не
является результатом проверки.

Предварительный отчёт должен ответить на три вопроса:

1. какой риск рассчитан;
2. что именно нашли в проверяемой сумме;
3. что найденный факт означает.

Он не принимает итоговое решение, не даёт рекомендацию по операции и не
рассказывает о состоянии DeepCheck.

## Аудитория и язык

Пользователь знаком с USDT, кошельками, биржами и мостами, но не обязан знать
`coverage`, `source-policy`, `transferFrom`, `hard evidence`, внутренние reason
codes и названия методов контрактов.

Текст:

- русский-first;
- говорит о сумме, доле, источнике, маршруте и роли адреса;
- показывает только подтверждённые структурированные факты;
- не превращает каждую нейтральную связь в разговор о краже;
- не использует LLM или raw reason text как автора или selector.

## Формат

```text
Откуда деньги — предварительный результат

Адрес: TGytcHDm9k4r6QPvine8c6A3WWaqTBZAZD

Предварительный риск: 🟠 78/100

Что нашли
• 83% проверяемой суммы пришло через мост UsdtOFT.

Вывод
Мост мог использоваться для обычного перевода между сетями или чтобы
затруднить проверку происхождения денег.

Границы проверки
Оставшиеся 17% не удалось проследить: история остановилась на общей
ликвидности сервиса.
```

Правила формата:

- эмодзи риска сохраняется;
- score показывается только при `scoreValid=true`;
- `Что нашли` содержит один главный факт и не больше одного дополнительного;
- `Вывод` объясняет смысл главного факта одним коротким абзацем;
- `Границы проверки` появляется только при существенном неполном покрытии;
- нет `Решения`, `Что делать`, `Что дальше` и упоминания DeepCheck;
- нет общего fallback `проверка завершена`.

Если `scoreValid=false`, числовой score не публикуется:

```text
Предварительный риск не рассчитан.

Границы проверки
Не удалось проследить 42% суммы: источник данных не вернул более старые
переводы.
```

`observedContextScore` остаётся в Admin/support и не выдаётся за
предварительный риск.

## Источник текста

Предварительный formatter использует тот же детерминированный каталог
структурированных фактов, что и итоговая wallet narrative. Режим отличается
только представлением:

- итоговый отчёт добавляет canonical decision и действие;
- предварительный Where показывает score, факт, смысл и ограничение;
- факты не содержат действие внутри себя, чтобы один и тот же факт можно было
  безопасно использовать в обоих режимах.

Raw `assessment.reasons`, `decisionReasons`, LLM verdict text и названия
контрактных методов не разбираются для пользовательского сообщения.

## Каталог сигналов

### Точные опасные факты

| Сигнал | Что нашли | Вывод |
|---|---|---|
| Проверяемый адрес в blacklist USDT | `Адрес находится в чёрном списке USDT. Переводы USDT для него заблокированы.` | `USDT на этом адресе нельзя свободно перевести.` |
| Exact approval-drain, адрес-жертва | `С кошелька списали 850 USDT после разрешения контракту. Проверяемый адрес — жертва.` | `Риск относится к подтверждённому списанию с этого кошелька.` |
| Exact approval-drain, первый получатель | `Кошелёк первым получил 3 857 USDT, списанные с двух других адресов.` | `Это первый получатель в подтверждённой дрейнер-цепочке.` |
| Exact approval-drain, следующее звено | `Кошелёк получил деньги от первого получателя дрейнера через один перевод. До него дошло 96% списанной суммы.` | `Адрес находится дальше по подтверждённому маршруту списанных средств.` |
| Exact bad label | `35% суммы пришло с адреса с подтверждённой меткой «фишинг».` | `Повышенный риск относится к этой части суммы.` |
| Mixer | `35% суммы прошло через миксер.` | `После миксера первоначальный источник денег нельзя надёжно проследить.` |
| Sanctioned service | `40% суммы пришло с сервиса, который на дату перевода находился под санкциями.` | `Это прямой санкционный источник выбранной части суммы.` |

Роль проверяемого адреса обязательна. Жертва не называется дрейнером, а
взаимодействие с контрактом не делает кошелёк первым получателем без exact
provenance.

### Контрактные сигналы

| Сигнал | Текст |
|---|---|
| Exact Verify20 для проверяемого контракта | `Контракт совпадает с подтверждённым шаблоном дрейнера Verify20.` |
| Drainer-like pattern без exact списания | `Маршрут связан с контрактом, который использует шаблон, часто встречающийся у дрейнеров. Подтверждённого списания в этой проверке нет.` |
| Неизвестный контракт | `Часть денег пришла через контракт, назначение которого не удалось определить.` |
| Обычный `transferFrom` | Не показывается отдельно: это технический механизм, а не самостоятельное доказательство. |
| GasFree Account | Считается обычным трассируемым и оцениваемым адресом на каждом hop. Сам статус не повышает риск. |
| Exact GasFree fee | `Перед переводом адрес оплатил комиссию сервису GasFree. Это технический платёж, а не источник основной суммы.` |

Комиссия GasFree показывается только при структурном settlement proof. Один
перевод на `TLntW9Z59LYY5KEi9cmwk3PKjQga828ird`, знакомая сумма или близкое
время не доказывают комиссионную роль.

### Мосты, биржи и сервисные границы

| Сигнал | Что нашли | Вывод |
|---|---|---|
| Один bridge route | `83% суммы пришло через мост UsdtOFT.` | `Это мог быть обычный перевод между сетями. Мосты также используют, чтобы затруднить проверку происхождения денег.` |
| Повторяющийся bridge route | `83% суммы пришло через мост UsdtOFT в десяти переводах.` | `Повторяющийся маршрут через мост сильнее скрывает первоначальный источник и повышает AML-риск.` |
| DEX/router/swap | `62% суммы прошло через обмен токенов на SunSwap.` | `Более ранний источник этой части суммы определить сложнее.` |
| Allowlisted CEX | `91% суммы пришло с Binance.` | `Это похоже на вывод средств с биржи. Более ранний источник скрыт общей ликвидностью Binance.` |
| Unknown CEX | `Деньги пришли через биржевой сервис, название которого не удалось подтвердить.` | `Трассировка остановилась на общей ликвидности сервиса.` |
| Unknown pool/liquidity | `27% суммы прошло через неизвестный пул ликвидности.` | `Первоначальный источник этой части суммы не установлен.` |
| Service boundary | `Маршрут дошёл до Bybit.` | `Установить более раннего отправителя по публичным данным нельзя: деньги клиентов объединены внутри сервиса.` |

Bridge/DEX wording не утверждает, что любой такой перевод является
отмыванием. Оно прямо сообщает две допустимые интерпретации и не подаёт мост
как нейтральный источник.

### HTX/Huobi

Дата санкционного назначения меняет юридическую классификацию, но не убирает
важность более ранней связи.

Перевод на дату санкций или позже:

```text
40% проверяемой суммы пришло с HTX. На дату перевода сервис находился под
санкциями Великобритании.

Это прямой санкционный источник выбранной части суммы.
```

Перевод до даты санкций:

```text
40% проверяемой суммы пришло с HTX до его включения в санкционный список.

Это историческая связь с HTX. Она остаётся существенным compliance-риском:
принимающая биржа может задержать средства и запросить дополнительную проверку
их происхождения.
```

До designation date нельзя писать `на дату перевода источник был
санкционным`. Нельзя и скрывать HTX за нейтральной формулировкой `обычная
биржа`. Это отдельный `REVIEW`-контекст, который должен быть виден независимо
от того, был ли перевод раньше официальной даты.

### Поведение кошелька

Поведенческий факт показывается только когда он реально участвует в score
Where, например через сохранённый Fast snapshot.

| Сигнал | Текст |
|---|---|
| Быстрый вывод большей части суммы | `После поступления кошелёк быстро перевёл 98% суммы дальше. Это похоже на транзитный кошелёк.` |
| Сбор поступлений | `Кошелёк собирает переводы с разных адресов и отправляет их дальше одной крупной суммой.` |
| Концентрация на CEX | `Большая часть поступлений переводится на Bybit. Это похоже на кошелёк для сбора и перемещения ликвидности.` |
| Новый адрес и крупный перевод | `Адрес создан недавно и почти сразу получил крупную сумму.` |
| Новый основной отправитель | `Основной отправитель раньше не переводил деньги на этот адрес.` |
| Долгий перерыв | `Перед этим переводом кошелёк долго не использовался.` |
| Длительная обычная связь | `Кошелёк регулярно получает деньги от этого отправителя. Связь не выглядит новой.` |

Collector/transit wording не использует `грязные деньги`, `кража` или
`касса бизнеса`, если таких фактов нет.

### Покрытие и неизвестный остаток

Покрытие не является причиной риска и выводится отдельно.

```text
Мы проследили происхождение 83% выбранной суммы.

Оставшиеся 17% не удалось проверить: история остановилась на общей
ликвидности моста.
```

Разрешённые причины остатка:

- источник данных не вернул более старые переводы;
- достигнут технический лимит;
- часть истории временно недоступна;
- сервис объединил деньги разных клиентов;
- деньги находились на кошельке раньше доступной истории;
- источник оставшейся суммы не установлен.

Слова `эпизод`, `anchor coverage`, `partial provenance` и raw technical codes
не показываются.

### Низкий риск

При низком score всё равно нужен конкретный результат:

```text
Что нашли
• Прослежено 96% суммы. Основная часть пришла с Binance.
• Подтверждённых опасных источников в проверенной части не найдено.

Вывод
Деньги похожи на обычный вывод с биржи. Более ранняя история скрыта общей
ликвидностью Binance.
```

Фраза относится только к проверенной сумме и не объявляет чистой всю историю
адреса.

## Отбор и дедупликация

Форматтер выполняет следующий порядок:

1. проверяет `scoreValid`;
2. выбирает typed fact, который создал dominant/winning risk layer;
3. добавляет не больше одного материального факта, который меняет понимание;
4. дедуплицирует один transfer/route/evidence episode между hard evidence,
   source policy, origin paths и Fast context;
5. добавляет coverage limitation выше optional GasFree detail;
6. форматирует текст по locale.

Приоритет главного факта:

1. blacklist проверяемого адреса;
2. exact approval-drain role;
3. exact sanctioned/bad/mixer source;
4. exact Verify20 для проверяемого контракта;
5. material bridge/DEX/HTX/unknown source-policy route;
6. поведенческий сигнал, который реально участвует в score;
7. чистый CEX-source;
8. coverage explanation для low/no-score результата.

Числовой score не может остаться без объяснения. Если структурированные данные
не содержат факта, который объясняет рассчитанный score, formatter не
использует общий fallback: он скрывает score, пишет о недостатке подтверждённых
данных и создаёт диагностическое событие для Admin/log.

## Что доступно только после DeepCheck

Предварительный Where не придумывает данные из будущего режима. В него не
попадают:

- first-hop blacklist/label coverage, если Where report её не сохраняет;
- Deep collector и relationship profiles;
- direct-counterparty facts, найденные только DeepCheck;
- роли, которые нельзя вывести из сохранённого Where approval provenance.

Если такой факт уже структурированно сохранён внутри Where report, его можно
показать. Наличие похожего raw reason недостаточно.

## Тестовые сценарии

1. Bridge 83%: мост назван, объяснён AML-смысл, остаток 17% объяснён отдельно.
2. Повторяющийся bridge route: количество переводов и доля суммы не смешаны.
3. HTX после designation: точный санкционный текст.
4. HTX до designation: историческая связь остаётся видимым compliance-risk и
   не называется санкционной на дату перевода.
5. Allowlisted CEX: назван источник и честная сервисная граница.
6. Exact approval-drain victim: адрес назван жертвой.
7. Exact first receiver: адрес назван первым получателем.
8. Drainer-like contract context без exact provenance: нет утверждения о
   подтверждённом списании.
9. Verify20 exact contract subject: точный template signal.
10. GasFree Account: principal оценивается; exact fee отделена от основной
    суммы.
11. Collector/transit: роль описана без презумпции криминального происхождения.
12. Partial valid coverage: score показан, остаток и причина видимы.
13. `scoreValid=false`: нет `/100`, observed context не подменяет score.
14. Low risk: named main source вместо общего `проверка завершена`.
15. Любой опубликованный score имеет хотя бы один конкретный факт, который его
    объясняет.
16. Нет `Что дальше`, DeepCheck copy, raw codes, method names и LLM text.

## Implementation surface

Минимальная реализация:

- расширить общий typed narrative catalogue только недостающими Where-фактами;
- добавить предварительный render profile без canonical action;
- заменить generic fallback в `formatWhereIsMoneyPreliminaryReport`;
- сохранить существующий score emoji helper;
- использовать существующие ranking/dedupe/body-budget primitives;
- добавить focused unit и bot integration tests;
- обновить `docs/knowledge/08-admin-and-bot-ux.md`,
  `09-current-decisions.md` и при необходимости `10-open-problems.md` после
  реализации.

Не меняются:

- scoring math и score floors;
- provenance tracing и indexing;
- canonical final disposition;
- Admin/support detailed reports;
- contract LLM classifier;
- legacy stored jobs.

## Self-review

- У каждого score есть конкретная причина.
- Preliminary message не принимает решение.
- HTX до санкционной даты не скрывается как обычная биржа.
- HTX после санкционной даты получает точную санкционную формулировку.
- Bridge описан как AML-risk с обычной и рискованной интерпретацией.
- Роль адреса предшествует generic behavior.
- Exact и contextual contract signals не смешаны.
- Coverage объяснено долей суммы и причиной остатка.
- GasFree principal остаётся оцениваемым; fee требует exact proof.
- Нет raw reasons, LLM copy и общего fallback.
